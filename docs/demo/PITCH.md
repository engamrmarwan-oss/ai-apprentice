# Tiro: pitch outline

Eight slides, about three minutes. Each slide has one point; the line under it is what to say.

## 1. The knowledge that leaves

**On the slide:** "Sabine retires in 18 months. 24 years of judgment leave with her."

**Say:** The process document shows the steps. It does not show why she holds one invoice and releases the next. That part was never written down, and a recording does not capture it either.

## 2. An apprentice, not a recorder

**On the slide:** Watches. Asks why. Maps. Teaches.

**Say:** Tiro watches an expert work in any web tool through screen share. It stays quiet while they work, asks at the pause, and keeps asking until it can explain the process back and the expert says yes.

## 3. When to ask, and what

**On the slide:** A turn within about ten seconds of a pause. One summary, one question.

**Say:** Timing is decided by code, not by a model: the screen is still, nobody is speaking, the moment is fresh. The question is picked so that the screen or the transcript does not already answer it, and every session asks for a limit, an exception and when to stop and ask.

## 4. The Work Map

**On the slide:** A step from the real map: screen moment, decision, the reason in the expert's words, its rules.

**Say:** A model proposes the map; code decides what stands. A step needs a screen moment and the expert's reason. A rule needs the expert's own words. Whatever is missing comes back as a question in the debrief, and the map counts only once the expert has confirmed the teach-back.

## 5. Teaching the new hire

**On the slide:** "I would approve it right away." Caught before the click.

**Say:** The new hire works a case the expert never showed. Tiro asks what they would do before they act, catches the wrong decision, and explains it with the expert's reason and the expert's screen at that moment. A mastery report shows what to practise next. The lesson can be held in the new hire's own language.

## 6. Built for any tool

**On the slide:** No tool name anywhere in the code.

**Say:** Tiro sees the tool only through screen share. The tool, the task, the questions and the rules are data, and a test fails the build if a workflow's words leak into a prompt. Our demo tool is Crystal, where Tiro's own requirements were written: Tiro learned how an expert reviews them.

## 7. What is real today

**On the slide:** Live on one address. Two sign-ins. Both roles.

**Say:** Capture, debrief, Work Map, tutor and mastery report run on the deployed app, with ElevenLabs agents as interviewer and tutor and Scribe for transcription. The Work Map can also be read by an outside agent over MCP, with a key per workflow. Not built yet: taking something off the record, and blurring personal data on screen.

## 8. The moonshot: people first, then agents

**On the slide:** The same map teaches the new hire today and guards an agent tomorrow.

**Say:** The steps and guardrails that teach a person are exactly what an agent needs to take the routine steps safely and stop where the expert would. Today's export is the first piece: any agent can load a confirmed Work Map. Next, each confirmed map becomes the baseline for the next session, so Tiro asks only about what changed, and one expert's map grows into the company's memory of how its work is really done.
